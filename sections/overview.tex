\section{Overview}
\label{sec:overview}

\dht is a decentralized storage system that can provide better durability guarantee by preventing overwhelming storage nodes.
Similar to other DSNs, \dht provides two operations
\begin{itemize}
    \item \fput(\var{k}, \var{v}) stores value \var{v} associated with key \var{k} on $r$ different nodes, where $r$ is the configured redundancy level.
    \item \fget(\var{k}) $\to$ \var{v} queries value that is associated with key \var{k}.
\end{itemize}
\noindent \dht can guarantee durability without assuming the storage nodes can store arbitrary size of contents.
Given the contents to be stored and the targeted redundancy level, \dht guarantees that
\begin{theorem}
    As long as the total storage supply is more than the required capacity (\ie the content size multiplied by the redundancy level) by a safe margin, the contents will be placed onto the storage nodes without exceeding the storage capacity of any storage node regardless of how much storage capacity each node has.
\end{theorem}
\noindent with high probability.
\footnote{The mathematical formalization of this theorem is work in progress.}
This guarantees that the placement groups are always \emph{valid} \ie they do not include any overwhelmed node, and the redundancy is actually stored.
Afterward, given capacity's failure rate \ie the maximum portion of capacity that can fail in a proof period (\ie fail to submit proof of storage) and redundancy level, the probability of data loss in the proof period can be derived just as other DHT networks.
What's unique to \dht is that the redundancy can always \emph{recover} to the expected level at the end of each proof period (given sufficient bandwidth resource), because the above theorem guarantees that the repair for the failed capacity and that new \fput will not overwhelm any storage node.
So the durability of a proof period will remain the same as the system running.
Thus, the MTTDL can be derived from the durability of a proof period as we previously do for DHT in \autoref{sec:bg:dsn}.

The key idea of \dht is to differentiate the discoverability storage nodes based on the available capacities they have.
As described in \autoref{sec:bg:dsn}, with DHT protocols like Kademlia and \dht, the placement groups are determined via \ffind operations, which returns a list of candidate nodes that are \emph{discovered} to be the closest ones to the storing content.
When invoking \ffind with uniformly random \vid, the more frequent a node is discovered by the \ffind operations, the more placement groups the node is included, and the more storing requests are routed to the node.

Although the virtual node approach is a simple and flexible design, we believe that differentiating nodes directly in the core DHT protocol is both necessary and a better approach.
By feeding DHT with more information instead of trying to ``workaround'' it, we trade a little more complexity in DHT design and implementation with a huge improvement in the quality of differentiation.
In this work the discoverability is differentiated only based on the availability capacities, but the differentiation should be useful in more context \eg bandwidth.

\paragraph{Node class and classified {\normalfont \texttt{xor}} distance.}
\dht performs a \emph{macro} differentiation on the nodes through a \emph{classification}.
In \dht every node is assigned a \emph{node class}, which participants in calculating the node's distance to an \vid:
\begin{verbatim}
dist(id,target_id,class) = (id^target_id) & (~0>>class)
\end{verbatim}
That is, the Kademlia's \texttt{xor} distance is masked out the highest bits, and the number of masked bits equals node's \vclass.
This is called the \emph{classified {\normalfont \texttt{xor}} distance}.
\autoref{fig:distance} shows an example of the same node with different classes.

\begin{figure}
    \centering
    \includegraphics[width=0.8\linewidth]{figs/distance}
    \caption{A node with different \vclass values.
    The blue regions are ``covered'' by the studied node, \ie, the node will be returned when \ffind \vid in the regions.}
    \label{fig:distance}
    \Description{}
\end{figure}

The effect of node class is similar to virtual node.
The classified \texttt{xor} distance for class 0 is identical to the original \texttt{xor} distance in Kademlia, and corresponds to one virtual node.
For class 1, the distance is same as calculating the original \texttt{xor} distance for both the node's \vid and its ``dual'' which flips the first bit of \vid, and takes the smaller distances of the two.
This effectively ``spawns'' two virtual nodes at the corresponding \vid{}s.
Similarly, we have class $c$ equals to have $2^c$ virtual nodes.
However, with node class each node still has one single \vid, so \ffind will only include each physical node at most once, which is unlike with virtual nodes where \ffind may return multiple \vid{}s that belong to the same physical node.

\paragraph{The power of two random choices (2RC).}
The node class is a powerful, exponential differentiation.
However, it is not without shortcoming.
If a node is discoverable for a \fput, it must be discoverable for the following \fget as well, otherwise the stored data cannot be retrieved.
This symmetry forbids us to adjust node class according to its current AC.
\lijl{We can discuss why this violates our target properties of \dht.}
In \dht the node class is set based on its total capacity.
Effectively the nodes are classified into different (exponential) levels of sizes, and we assign an initial discoverability for each level accordingly.

However, that does not reflect the \emph{real time} differences.
Even for nodes that are classified into the same size level, their AC probably differs at a given instant.
This may due to probabilistic fluctuation of their empirical discoverability, or the contents stored on them expire at different rates.

To compensate for the real time dynamics, \dht performs \emph{micro} differentiation with 2RC.
However unlike the typical employment of 2RC that pick the nodes with lighter load, \dht picks the nodes with more AC.
By \emph{balancing} the AC of the nodes, \dht manages to \emph{differentiate} the discoverability of nodes with different AC, as the nodes with more AC will be more discoverable until their AC is balanced with the others.

\paragraph{Simulation setup.}
We than verify the effectiveness of \sys with various simulations.
Without further statement the simulations are performed with 12k nodes, and each node can store $2^{10}$ contents at minimum and $2^{17}$ at maximum.
This means the node classes are between 10 and 17.
The node capacities follow a shifted Zipf distribution~\cite{zipf} with skewness set to $1$.
Besides \sys, we also simulate a vanilla DHT as the compared baseline.
We replicate each content with 3 copies.
Finally, we repeat each simulation 100 times and report the average and error of the results.

\begin{figure}
    \centering
    \includegraphics[width=\linewidth]{data/simulation/graphs/capacity-freq}
    \caption{The CDF and per-class averages of capacity discoverability.}
    \label{fig:freq}
    \Description{}
\end{figure}

In \autoref{fig:freq} we show the CDF and per-class averages of \emph{capacity discoverability}.
In this simulation we perform 1 million \ffind with uniformly random \vid{}s.
The node discoverability is measured by the frequencies of the nodes appears in the results, and we report capacity discoverability, which is node discoverability divided by the node's capacity.
The CDF shows that \dht's capacity discoverability is more balanced while the vanilla DHT has a long tail \ie some capacity has much higher discoverability than the others.
The per-class averages reveal the source of this difference: in the vanilla DHT, the storage nodes with lower classes has exponentially higher capacity discoverability, while in \sys, thanks to the macro-differentiation, capacities that belong to various sizes of nodes have balanced discoverability.

Then, we perform 10 million \fput of random contents into the simulated DSNs.
With \dht there is no single node that is overwhelmed, while the results with the vanilla DHT is shown in \autoref{fig:overwhelm} and described in \autoref{sec:bg:problem}.

To further study how well \dht can balance the availability capacity, in \autoref{fig:ac-distr} we plot the AC of all nodes with $2^{10}$ capacity, and the average AC of nodes of different sizes.
In \dht the nodes with $2^{10}$ capacity have basically all their capacities available, because \dht tends to first utilize the larger nodes for their higher AC.
As shown in the line plot, the AC of larger nodes is significantly lower than the vanilla DHT.
The saw shape line is because of the error introduced by node class: the node capacity is approximated with the closest power-of-two, which causes over- and under-utilization of nodes whose capacities are in the middle of consecutive power-of-two.

Finally, we perform a stress simulation by continuing \fput random contents (with random eviction on overwhelmed nodes) until data loss, and report the overall utilization in \autoref{fig:util-loss}.
We simulate with different skewness of node capacities, from 1 where the capacities are highly nonuniform, to 2 where most of the nodes have the same $2^{10}$ capacity.
We further perform ablation study on the effectiveness of the macro- and micro-differentiation.
The results show that both differentiation provide improvement.
The macro-differentiation is effective with imbalance capacity, and degrade to vanilla DHT when the skewness is high and most nodes have the same node class.
The micro-differentiation, on the other hand, yields perfect utilization at high skewness, but becomes ineffective when the capacity is imbalanced.
\dht combines the two improvement and outperforms vanilla DHT by more than 60\% utilization at any skewness, and can reach at most 100\% utilization at high skewness.
