\section{Design and Preliminary Evaluation}
\label{sec:overview}

In this section, we introduce \dht, a novel DHT design specifically optimized for effective overall utilization of heterogeneous storage nodes (\autoref{sec:bg:problem}).
As will be demonstrated, the key to enhancing effective overall utilization lies in preferentially allocating nodes with the largest available storage spaces to placement groups first, so the remaining storage resources on the nodes are \emph{equalized}.
The central concept of \dht is to assign varying \emph{storing likelihoods} -- the probabilities of being included in the placement groups of random keys and storing associated data -- to nodes based on their respective available storage spaces.
This concept is realized through two design components.
The first component is classified distance, which shares similarities with the weighted equation proposed by \cite{schindelhauer2005weighted} but features a simpler form and does not necessitate the use of virtual nodes.
The second component involves leveraging the power of two random choices~\cite{sitaraman2001power}.
We will now provide an intuitive overview of these design elements, with a detailed DHT specification reserved for future work.
The section concludes with a discussion of preliminary results.

\paragraph{Equalizing available storage spaces.}
Imagine two storage nodes, one with $100\times$ the space of the other. How do we store the most data without overwhelming either?
A basic idea is to make the larger node $100\times$ more likely to receive storage requests.
However, a better way is to initially prevent the smaller node from storing anything until the larger node's remaining space equals the smaller one's. Then, both become equally likely to store.
For instance, if the larger node holds 100 data items and the smaller holds one, the basic approach gives a ~1\% chance of overwhelming the small node per item, and only a 37.3\% chance of storing 99 items without overwhelming it (\ie, all data landing on the large node).
The better approach lets us always store the first 99 items with 0\% risk of overwhelming either.
Thus, we shouldn't \emph{statically} assign storage request likelihood based on total space.
Instead, these likelihoods should be \emph{dynamically} adjusted, so nodes ideally aren't used if others have more free space\footnote{
    In practice, they're still needed for fault tolerance by distributing data copies.
}.

Second, we introduce the power of two random choices to probabilistically mitigate the resulting inaccuracies.

\paragraph{Classified distance.}
\lijl{Should start with high-level idea of ``class'' and its association with storage capacity.}
As described in \autoref{sec:bg:dht}, Kademlia's distance $d$ between a key $k$ and a node with identity $id$ is computed as $k\ \texttt{xor}\ id$.
We associate each node with a \emph{class}, a non-negative integer constrained by the bit length of $id$ and $k$ (\eg, less than 256 for a $2^{256}$ hash domain).
Nodes can set their class values to the base-two logarithm of their storage capacities, meaning the class value increments by one for every doubling of capacity.
We then modify Kademlia's distance equation to incorporate the node's class $c$:
\[
    d'(k, id, c)=(k\ \texttt{xor}\ id)\ \texttt{mod}\ 2^{K-c}
\]
where $K$ represents the bit length of $k$ and $id$ (e.g., $K=256$).
We term $d'$ the \emph{classified distance equation}.
Subsequently, Kademlia's data placement equation is adapted to utilize $d'$ in place of $d$:
\begin{multline*}
    G_k=\{n_i\mid{}d'(k,ID[n_i],C[n_i])<d'(k,ID[n],C[n]),\\
    n\in{}\mathfrak{N}\setminus{}G_k,i\in{}[1,\dots,r]\}
\end{multline*}
where $C$ denotes the mapping from nodes to their classes.

    \caption{``Key coverage'' of a node with identity $id=0100$ for varying class values.
    The shaded regions represent the portions of the hash domain for which this node has the smallest classified distance.}
    \label{fig:distance}

\end{figure}

One way to intuitively understand the classified distance equation is that it effectively assigns multiple virtual identities to a single physical node, the number of which depends on the node's class.
Each of these virtual identities then calculates a distance to a given key using the original Kademlia distance equation ($d$).
Finally, the smallest distance among those calculated by the virtual identities is selected as the classified distance ($d'$).
\autoref{fig:distance} provides a visual example, where the node under consideration is marked with a star, and other nodes are marked with circles.
When the node with $id=0100$ has a class $c=1$, it is effectively ``assigned'' an additional virtual identity $id_1=1100$ (represented as a ghost star in the illustration). For a key $k=1101$, the classified distance $d'$ yields a value of $1$, which is the smaller of the original distances $d(id,k)$ and $d(id_1,k)$.
When the class $c$ increases to $2$, two more virtual identities are associated with the node, and so forth.
Consequently, as its class increases, the node effectively becomes ``closer'' to a greater number of keys within the hash domain, increasing its likelihood of being selected for storing those keys, as indicated by the expanding gray regions.
The range of keys for which a node is responsible for storing approximately doubles with each increment of its class by one, mirroring a doubling of its storage capacity.
Ultimately, the range of storing keys becomes proportional to the node's storage capacity, implying that the probability of a node receiving a storage request is proportional to its capacity.

While the resulting effect is similar to that achieved by virtual nodes, the fundamental distinction lies in the fact that we do not \emph{actually} assign multiple identities to a single physical node.
The DSNs' underlying assumption that each node identity corresponds to a unique physical node (i.e., a distinct failure domain) remains valid.

Instead of operating with an unmodified DHT and indirectly representing heterogeneity in an ``equivalent'' manner, classified distance directly extends the DHT to be \emph{heterogeneity-aware}. Its consistent hashing scheme now inherently incorporates class values that reflect the heterogeneity of nodes.
We contend that modifying the DHT design is a superior approach for simultaneously addressing heterogeneity and the correct modeling of storage failure correlations.

To accommodate classified distance, both the node record retention policy and the iterative lookup procedure (\autoref{sec:bg:dht}) require corresponding modifications.
We will elaborate on these details and a reconfiguration protocol that allows nodes to adjust their classes in response to dynamic changes in their storage capacities in future work.
However, it is important to note that nodes must relocate the placement groups of their stored data and transfer them accordingly before decreasing their class values.
This is crucial to prevent the DHT from directing subsequent access requests to the newly reallocated nodes of the placement groups before they actually possess the data.

\paragraph{The power of two random choices (2RC)\@.}
As previously discussed, classified distance, while an improvement, still carries a non-negligible probability of directing storage requests to nodes with less available storage space.
To mitigate this, we integrate 2RC into Kademlia's lookup procedure.
Each data item has a single key, which is then hashed twice using two different hashing algorithms, resulting in two distinct hash values. The lookup process then identifies the placement groups corresponding to both of these hash values.
When a node intends to store or modify data, the storage request is directed to the placement group whose constituent nodes exhibit greater available storage space \lijl{how is this being done? First check both groups?}.
Conversely, when a node seeks to retrieve data, the retrieval request is sent to both placement groups, and the group containing the data will respond.

In most standard applications, 2RC selects two (homogeneous) backend nodes with uniform randomness.
However, in our implementation, it operates in conjunction with the biased randomness introduced by the classified distance, which enhances its performance in heterogeneous scenarios.
Before the entire storage network approaches saturation (at which point our objective of optimizing overall utilization has largely been achieved!), nodes with larger capacities are likely to have more available storage space than smaller ones.
The classified distance reduces the probability of selecting smaller nodes, and the likelihood of selecting two small nodes simultaneously is even lower than selecting one.
And it is only when it happens that we would utilize nodes with less available space.

In essence, the design of \dht comprises two components operating at different \emph{scales}.
Classified distance functions at the global level, influencing all nodes but with a degree of inflexibility and approximation.
Conversely, 2RC operates at the local level, affecting only nodes within two placement groups at any given time, yet providing a more precise adjustment.
By integrating these two components, \dht can effectively optimize the overall storage utilization as intended.
The following section presents our preliminary findings, demonstrating the effectiveness of \dht.

\paragraph{Node class and classified {\normalfont \texttt{xor}} distance.}
\dht performs a \emph{macro} differentiation on the nodes through a \emph{classification}.
In \dht every node is assigned a \emph{node class}, which participants in calculating the node's distance to an \vid:
\begin{verbatim}
dist(id,target_id,class) = (id^target_id) & (~0>>class)
\end{verbatim}
That is, the Kademlia's \texttt{xor} distance is masked out the highest bits, and the number of masked bits equals node's \vclass.
This is called the \emph{classified {\normalfont \texttt{xor}} distance}.
\autoref{fig:distance} shows an example of the same node with different classes.

\begin{figure}
    \centering
    \includegraphics[width=0.8\linewidth]{figs/distance}
    \caption{A node with different \vclass values.
    The blue regions are ``covered'' by the studied node, \ie, the node will be returned when \ffind \vid in the regions.}
    \label{fig:distance}
    \Description{}
\end{figure}

The effect of node class is similar to virtual node.
The classified \texttt{xor} distance for class 0 is identical to the original \texttt{xor} distance in Kademlia, and corresponds to one virtual node.
For class 1, the distance is same as calculating the original \texttt{xor} distance for both the node's \vid and its ``dual'' which flips the first bit of \vid, and takes the smaller distances of the two.
This effectively ``spawns'' two virtual nodes at the corresponding \vid{}s.
Similarly, we have class $c$ equals to have $2^c$ virtual nodes.
However, with node class each node still has one single \vid, so \ffind will only include each physical node at most once, which is unlike with virtual nodes where \ffind may return multiple \vid{}s that belong to the same physical node.

\paragraph{The power of two random choices (2RC).}
The node class is a powerful, exponential differentiation.
However, it is not without shortcoming.
If a node is discoverable for a \fput, it must be discoverable for the following \fget as well, otherwise the stored data cannot be retrieved.
This symmetry forbids us to adjust node class according to its current AC.
\lijl{We can discuss why this violates our target properties of \dht.}
In \dht the node class is set based on its total capacity.
Effectively the nodes are classified into different (exponential) levels of sizes, and we assign an initial discoverability for each level accordingly.

However, that does not reflect the \emph{real time} differences.
Even for nodes that are classified into the same size level, their AC probably differs at a given instant.
This may due to probabilistic fluctuation of their empirical discoverability, or the contents stored on them expire at different rates.

To compensate for the real time dynamics, \dht performs \emph{micro} differentiation with 2RC.
However unlike the typical employment of 2RC that pick the nodes with lighter load, \dht picks the nodes with more AC.
By \emph{balancing} the AC of the nodes, \dht manages to \emph{differentiate} the discoverability of nodes with different AC, as the nodes with more AC will be more discoverable until their AC is balanced with the others.

\paragraph{Simulation setup.}
\lijl{For the workshop paper, this part could be condensed.}
We evaluate \dht using a simulated DSN.
Unless otherwise specified, the simulations involve 12,000 nodes, each with a storage capacity ranging from $2^{10}$ data units (minimum) to $2^{17}$ data units (maximum), resulting in node class values between 10 and 17.
The distribution of node capacities follows a shifted Zipf distribution~\cite{zipf} with a skewness parameter of 1.
In addition to \dht, we simulate a standard Kademlia DHT as a baseline for comparison.
Each piece of content is replicated three times, i.e., $r=3$.
Finally, each simulation is run 100 times, and we report the average and standard error of the results.

\begin{figure}
    \centering
    \includegraphics[width=0.7\linewidth]{data/simulation/graphs/util}
    \caption{Effective overall utilization achieved by DSNs.}
    \label{fig:util-loss}
    \Description{}
\end{figure}

Initially, we conducted 10 million storage attempts with uniformly random keys on the simulated DSNs.
With \dht, all storage attempts were successful, and no node exhausted its storage space.
The outcomes for Kademlia are illustrated in \autoref{fig:overwhelm} and detailed in \autoref{sec:bg:problem}.

Next, we conducted a stress simulation by continuously storing data with random keys (with random eviction upon node storage exhaustion) until data loss occurred, and we report the overall utilization in \autoref{fig:util-loss}.
We performed simulations with varying skewness of node capacities, ranging from 1 (highly diverse capacities) to 2 (where almost all nodes have the same $2^{10}$ capacity).
We also conducted an ablation study to assess the effectiveness of the classified distance and 2RC designs independently.
The results indicate that both designs contribute to improved utilization, but in different scenarios.
Classified distance is particularly effective when node capacities are diverse (low skewness), but its performance approaches that of Kademlia as the skewness increases and most nodes converge to the same (lowest) node class.
Conversely, 2RC achieves near-perfect utilization under high skewness but becomes less effective when capacity heterogeneity is significant.
Ultimately, \dht combines the benefits of both classified distance and 2RC, outperforming Kademlia by over 60\% in utilization across all skewness levels and reaching almost 100\% utilization at high skewness.
These simulation results demonstrate that \dht effectively achieves its goal of optimizing effective overall utilization, and both its constituent designs perform as expected.

The CDF reveals that \dht's likelihood distribution is more balanced than Kademlia's, which exhibits a long tail, indicating that some storage units have a significantly higher probability of being utilized than others.
The per-class averages highlight the origin of this disparity: in Kademlia, nodes with lower class values have exponentially higher storing likelihoods per unit of storage.
This occurs because these nodes have exponentially smaller capacities, a heterogeneity that Kademlia's distance definition does not account for, leading to the storage units of these smaller nodes being assigned disproportionately high storing likelihoods.

The subsequent evaluation examines how well DSNs equalize the available storage space across nodes.
We store an equivalent amount of data in both Kademlia and \dht until the first node in Kademlia reaches its capacity limit.
At this point, we capture a snapshot of the available storage space on all nodes in both networks.
In \autoref{fig:ac-distr}, the left plot shows the distribution of available space for nodes with the smallest capacity of $2^{10}$ units, while the right plot displays the average available space for nodes of different capacity sizes.
In \dht, the nodes with the smallest capacity retain almost their entire storage space, indicating minimal utilization, and nodes with larger capacities in \dht have significantly less available space compared to their counterparts in Kademlia.
Conversely, Kademlia consumes available space from nodes of all capacities and has already exhausted one of the smallest nodes.
The saw-tooth pattern observed in the \dht plot arises from the approximation inherent in the node class assignment: node capacity is rounded to the nearest power of two, leading to over-utilization of nodes whose capacities fall slightly below a power of two and under-utilization of those slightly above.
