\dht maintains most conventional DHT properties: decentralization, scalability, availability, and a flat key space~\cite{chord}.
However, it diverges from the typical load balancing of DHTs and consistent hashing, which uniformly distribute keys.
Instead, \dht assigns keys in a specific, non-uniform way to prevent any node from being overloaded as much as possible, thus optimizing for effective overall utilization (\autoref{sec:bg:problem}).

In this section, we present the two design components that enable this functionality.
The first component involves applying classified distance to direct the storage workload to nodes proportionally to their capacities, thus balancing the utilized likelihood per unit of storage across the nodes.
This approach shares similarities with the weighted equation proposed by \cite{schindelhauer2005weighted} but features a simpler form and avoids the use of virtual nodes.
While classified distance alone can improve upon Kademlia, we will demonstrate that superior performance can be achieved by equalizing the available storage space across nodes.
The power of two random choices is the second component we introduce to accomplish this equalization, based on the classified distance.

\paragraph{Classified distance.}
\lijl{Should start with high-level idea of ``class'' and its association with storage capacity.} \gd{Done.}
We propose classifying nodes based on their storage capacities, allowing the DHT to utilize nodes from different classes in a differentiated manner by employing distinct methods to calculate their distances to the data keys.
As described in \autoref{sec:bg:dht}, Kademlia's distance $d$ between a key $k$ and a node with identity $id$ is computed as $k\ \texttt{xor}\ id$.
We associate each node with a \emph{class}, a non-negative integer constrained by the bit length of $id$ and $k$ (\eg, less than 256 for a $2^{256}$ hash domain).
Nodes set their class values to the base-two logarithm of their storage capacities, meaning the class value increments by one for every doubling of capacity.
We then modify Kademlia's distance equation to incorporate the node's class $c$:
\[
    d'(k, id, c)=(k\ \texttt{xor}\ id)\ \texttt{mod}\ 2^{K-c}
\]
where $K$ represents the bit length of $k$ and $id$ (e.g., $K=256$).
We term $d'$ the \emph{classified distance equation}.
Subsequently, Kademlia's data placement equation is adapted to utilize $d'$ in place of $d$:
\begin{multline*}
    G_k=\{n_i\mid{}d'(k,ID[n_i],C[n_i])<d'(k,ID[n],C[n]),\\
    n\in{}\mathfrak{N}\setminus{}G_k,i\in{}[1,\dots,r]\}
\end{multline*}
where $C$ denotes the mapping from nodes to their classes.

    The shaded regions represent the portions of the hash domain for which this node has the smallest classified distance.}

One way to intuitively understand the classified distance equation is that it effectively assigns multiple virtual identities to a single physical node, the number of which depends on the node's class.
Each of these virtual identities then calculates a distance to a given key using the original Kademlia distance equation ($d$).
Finally, the smallest distance among those calculated by the virtual identities is selected as the classified distance ($d'$).
\autoref{fig:distance} provides a visual example, where the node under consideration is marked with a star, and other nodes are marked with circles.
When the node with $id=0100$ has a class $c=1$, it is effectively ``assigned'' an additional virtual identity $id_1=1100$ (represented as a ghost star in the illustration). For a key $k=1101$, the classified distance $d'$ yields a value of $1$, which is the smaller of the original distances $d(id,k)$ and $d(id_1,k)$.
When the class $c$ increases to $2$, two more virtual identities are associated with the node, and so forth.
Consequently, as its class increases, the node effectively becomes ``closer'' to a greater number of keys within the hash domain, increasing its likelihood of being selected for storing those keys, as indicated by the expanding gray regions.
The range of keys for which a node is responsible for storing approximately doubles with each increment of its class by one, mirroring a doubling of its storage capacity.
Ultimately, the range of storing keys becomes proportional to the node's storage capacity, implying that the probability of a node receiving a storage request is proportional to its capacity.

While the resulting effect is similar to that achieved by virtual nodes, the fundamental distinction lies in the fact that we do not \emph{actually} assign multiple identities to a single physical node.
The DSNs' underlying assumption that each node identity corresponds to a distinct failure domain (\autoref{sec:bg:works}) remains valid.
Rather than concealing the complexity of node heterogeneity from the DHT, we choose to expose it, enabling the DHT to perform more effectively.

\paragraph{Equalizing available storage spaces.}
Imagine two storage nodes, one with $100\times$ the space of the other. How do we store the most data without overwhelming either?
The classified distance would make the larger node $100\times$ more likely to receive storage requests.
However, a better way is to initially prevent the smaller node from storing anything until the larger node's remaining space equals the smaller one's. Then, both become equally likely to store.
For instance, if the larger node holds 100 data items and the smaller holds one, the basic approach gives a ~1\% chance of overwhelming the small node per item, and only a 37.3\% chance of storing 99 items without overwhelming it (\ie, all data landing on the large node).
The better approach lets us always store the first 99 items with 0\% risk of overwhelming either.
Therefore, it is not enough for data to simply have a higher probability of landing on nodes with greater capacity; we should actively \emph{enforce} its placement on nodes with more available space.
By \emph{equalizing} the available space across nodes, smaller nodes will remain unused as long as larger nodes have more available space than them\footnote{
    In practice, they are still necessary for fault tolerance by distributing data copies.
}, thus preventing the smaller nodes from running out of space before the larger ones.

\paragraph{The power of two random choices (2RC)\@.}
2RC is our answer for equalizing available space.
Each data item has a single key, which is then hashed twice using two different hashing algorithms, resulting in two distinct hash values. The lookup process then identifies the placement groups corresponding to both of these hash values.
When a node intends to store or modify data, the storage request is directed to the placement group whose constituent nodes exhibit greater available storage space, which can be determined during the placement group discovery.
 \lijl{how is this being done? First check both groups?}\gd{Yes and clarified.}
Conversely, when a node seeks to retrieve data, the retrieval request is sent to both placement groups, and the group containing the data will respond.

In most standard applications, 2RC selects two (homogeneous) backend nodes with uniform randomness.
However, in our implementation, it operates in conjunction with the biased randomness introduced by the classified distance, which enhances its performance in heterogeneous scenarios.
Before the entire storage network approaches saturation (at which point our objective of optimizing overall utilization has largely been achieved!), nodes with larger capacities are likely to have more available storage space than smaller ones.
The classified distance reduces the probability of selecting smaller nodes, and the likelihood of selecting two small nodes simultaneously is even lower than selecting one.
And it is only when it happens that we would utilize nodes with less available space.

In essence, the design of \dht comprises two components operating at different \emph{scales}.
Classified distance functions at the global level, influencing all nodes but with a degree of inflexibility and approximation.
Conversely, 2RC operates at the local level, affecting only nodes within two placement groups at any given time, yet providing a more precise adjustment.
By integrating these two components, \dht can effectively optimize the overall storage utilization as intended.

\paragraph{Node class and classified {\normalfont \texttt{xor}} distance.}
\dht performs a \emph{macro} differentiation on the nodes through a \emph{classification}.
In \dht every node is assigned a \emph{node class}, which participants in calculating the node's distance to an \vid:
\begin{verbatim}
dist(id,target_id,class) = (id^target_id) & (~0>>class)
\end{verbatim}
That is, the Kademlia's \texttt{xor} distance is masked out the highest bits, and the number of masked bits equals node's \vclass.
This is called the \emph{classified {\normalfont \texttt{xor}} distance}.
\autoref{fig:distance} shows an example of the same node with different classes.

\begin{figure}
    \centering
    \includegraphics[width=0.8\linewidth]{figs/distance}
    \caption{A node with different \vclass values.
    The blue regions are ``covered'' by the studied node, \ie, the node will be returned when \ffind \vid in the regions.}
    \label{fig:distance}
    \Description{}
\end{figure}

The effect of node class is similar to virtual node.
The classified \texttt{xor} distance for class 0 is identical to the original \texttt{xor} distance in Kademlia, and corresponds to one virtual node.
For class 1, the distance is same as calculating the original \texttt{xor} distance for both the node's \vid and its ``dual'' which flips the first bit of \vid, and takes the smaller distances of the two.
This effectively ``spawns'' two virtual nodes at the corresponding \vid{}s.
Similarly, we have class $c$ equals to have $2^c$ virtual nodes.
However, with node class each node still has one single \vid, so \ffind will only include each physical node at most once, which is unlike with virtual nodes where \ffind may return multiple \vid{}s that belong to the same physical node.

\paragraph{The power of two random choices (2RC).}
The node class is a powerful, exponential differentiation.
However, it is not without shortcoming.
If a node is discoverable for a \fput, it must be discoverable for the following \fget as well, otherwise the stored data cannot be retrieved.
This symmetry forbids us to adjust node class according to its current AC.
\lijl{We can discuss why this violates our target properties of \dht.}
In \dht the node class is set based on its total capacity.
Effectively the nodes are classified into different (exponential) levels of sizes, and we assign an initial discoverability for each level accordingly.

However, that does not reflect the \emph{real time} differences.
Even for nodes that are classified into the same size level, their AC probably differs at a given instant.
This may due to probabilistic fluctuation of their empirical discoverability, or the contents stored on them expire at different rates.

To compensate for the real time dynamics, \dht performs \emph{micro} differentiation with 2RC.
However unlike the typical employment of 2RC that pick the nodes with lighter load, \dht picks the nodes with more AC.
By \emph{balancing} the AC of the nodes, \dht manages to \emph{differentiate} the discoverability of nodes with different AC, as the nodes with more AC will be more discoverable until their AC is balanced with the others.
