\section{Overview}
\label{sec:overview}

The key idea of \dht is to differentiate the discoverability storage nodes based on the available capacities they have.
As described in \autoref{sec:bg:dsn}, with DHT protocols like Kademlia and \dht, the placement groups are determined via \ffind operations, which returns a list of candidate nodes that are \emph{discovered} to be the closest ones to the storing content.
The more frequent a node is discovered by the \ffind operations, the more placement groups the node is included, and the more storing requests are routed to the node.
In Kademlia, the frequency of \ffind returning every node is the same, and the definition of \emph{discoverability} is usually binary: whether the node ever appears in any \ffind result.
\xxx{Cite}
In the contrary, \dht is able to \ffind nodes with different frequencies, and discoverability is extended into an ordinal concept: given the discovered \vid uniformly distributed across the \vid{}'s domain space, the more probable a node's \vid is returned, the more discoverable the node is.

Although the virtual node approach is a simple and flexible design, we believe that differentiating nodes directly in the core DHT protocol is both necessary and a better approach.
By feeding DHT with more information instead of trying to ``workaround'' it, we trade a little more complexity in DHT design and implementation with a huge improvement in the quality of differentiation.
In this work the discoverability is differentiated only based on the availability capacities, but the differentiation should be useful in more context \eg bandwidth.

\paragraph{Node class and classified {\normalfont \texttt{xor}} distance.}
\dht performs a \emph{macro} differentiation on the nodes through a \emph{classification}.
In \dht every node is assigned a \emph{node class}, which participants in calculating the node's distance to an \vid:
\begin{verbatim}
dist(id,target_id,class) = (id^target_id) & (~0>>class)
\end{verbatim}
That is, the Kademlia's \texttt{xor} distance is masked out the highest bits, and the number of masked bits equals node's \vclass.
This is called the \emph{classified {\normalfont \texttt{xor}} distance}.
\autoref{fig:distance} shows an example of the same node with different classes.

\begin{figure*}
    \centering
    \includegraphics[width=\linewidth]{figs/distance}
    \caption{A node with different \vclass values.
    The blue regions are ``covered'' by the studied node, \ie, the node will be returned when \ffind \vid in the regions.}
    \label{fig:distance}
\end{figure*}

The effect of node class is similar to virtual node.
The classified \texttt{xor} distance for class 0 is identical to the original \texttt{xor} distance in Kademlia, and corresponds to one virtual node.
For class 1, the distance is same as calculating the original \texttt{xor} distance for both the node's \vid and its ``dual'' which flips the first bit of \vid, and takes the smaller distances of the two.
This effectively ``spawns'' two virtual nodes at the corresponding \vid{}s.
Similarly, we have class $c$ equals to have $2^c$ virtual nodes.
However, with node class each node still has one single \vid, so \ffind will only include each physical node at most once, which is unlike with virtual nodes where \ffind may return multiple \vid{}s that belong to the same physical node.

\paragraph{The power of two random choices (2RC).}
The node class is a powerful, exponential differentiation.
However, it is not without shortcoming.
If a node is discoverable for a \fput, it must be discoverable for the following \fget as well, otherwise the stored data cannot be retrieved.
This symmetry forbids us to adjust node class according to its current AC.
In \dht the node class is set based on its total capacity.
Effectively the nodes are classified into different (exponential) levels of sizes, and we assign an initial discoverability for each level accordingly.

However, that does not reflect the \emph{real time} differences.
Even for nodes that are classified into the same size level, their AC probably differs at a given instant.
This may due to probabilistic fluctuation of their empirical discoverability, or the contents stored on them expire at different rates.
\xxx{Describe graph.}

To compensate for the real time dynamics, \dht performs \emph{micro} differentiation with 2RC.
However unlike the typical employment of 2RC that pick the nodes with lighter load, \dht picks the nodes with more AC.
By \emph{balancing} the AC of the nodes, \dht manages to \emph{differentiate} the discoverability of nodes with different AC, as the nodes with more AC will be more discoverable until their AC is balanced with the others.
