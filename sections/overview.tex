\section{Design and Preliminary Evaluation}
\label{sec:overview}

In this section we propose \dht, a novel DHT design that is optimized for \emph{effective overall utilization} of heterogeneous storage nodes (\autoref{sec:bg:problem}).
As shown later, the key to improve effective overall utilization is to allocate nodes with more available storage spaces into more placement groups, so the storage resources on the nodes are exhausted in the same pace.
\dht's main idea is to assign different \emph{storing likelihoods}, \ie, the likelihoods of being assigned into the placement groups of random keys and storing data for them, to the nodes with different available storage spaces.
It realizes this idea with two designs.
The first design is classified distance, which is similar to the weighted equation proposed by \cite{schindelhauer2005weighted}, but features a simpler design and does not require the assistance from virtual node.
The second design employs the power of two random choices~\cite{sitaraman2001power}.
Next, we give intuitions on the designs and refer to future work for a detailed DHT specification.
We conclude the section by discussing the preliminary results.

\paragraph{Equalize the available storage spaces.}
Given two storage nodes, one with $100\times$ capacity than the other one, how can we store as much data into them as possible without overwhelming any of them?
One naive approach is to set the likelihood of the store request landing on the larger node $100\times$ to the likelihood of landing on the smaller one.
However, a better approach would be set the storing likelihood of the smaller node to 0, until the larger one has stored lots of data and has exactly same available space as the smaller one, then we adjust the storing likelihood of the smaller node to be the same as the larger one.
Let's say the larger node can store 100 data while the smaller one can store only one.
With the naive approach, we have around $1\%$ probability of exhausting the smaller node on every data placement, and the probability of storing 99 data without exhausting the smaller node (\ie, all store requests landed on the larger node) is only $37.3\%$.
While with the better approach, we can store the first 99 data and $100\%$ not exhaust any node.
In conclusion, we should not \emph{statically} assign the likelihood of each node receiving store requests based on their total capacities.
Instead, the likelihoods should be \emph{dynamically} adjusted so that ideally the nodes are not utilized at all when there exists nodes who have more available spaces than them.

This dynamical adjustment is obviously challenging in decentralization networks.
Our solution consists of two designs.
We first replace Kademlia's distance definition with classified distance to provide ``a first approximation'', achieving the effect of the naive approach.
Then we introduce the power of two random choices to probabilistically offset the error.

\paragraph{Classified distance.}
Recall from \autoref{sec:bg:dht} that Kademlia's distance $d$ between a key $k$ and a node whose identity is $id$ is calculated as $k\ \texttt{xor}\ id$.
We associate each node with a \emph{class}, a non-negative integer whose value is limited by the bit length of $id$ and $k$ (\eg, less than 256 for a $2^{256}$ hash space).
Nodes can set their class values to the logarithm of their storage capacities, so the class value increases by one when the capacity doubles.
Then, we modify Kademlia's distance equation to take the node's class $c$ into account
\[
    d'(k, id, c)=(k\ \texttt{xor}\ id)\ \texttt{mod}\ 2^{K-c}
\]
where $K$ is the bit length of $k$ and $id$ (\eg, $K=256$).
We call $d'$ the \emph{classified distance equation}.
Then, the data placement equation of Kademlia is modified to use $d'$ instead of $d$
\begin{multline*}
    G_k=\{n\mid{}d'(k,ID[n_i],C[n_i])<d'(k,ID[n],C[n]),\\
    n\in{}\mathfrak{N}\setminus{}G_k,i\in{}[1,\dots,r]\}
\end{multline*}
where $C$ is the mapping from nodes to their classes.

One way to intuitively perceive classified distance equation is that, it effectively assigns multiple identities to a node, the number of whom depends on the node's class.
And each of those identities calculates a distance with the original equation $d$.
And finally, the smallest distance produced by the identities is selected.
\autoref{fig:distance} illustrates a concrete example, where the studied node is marked with star and other nodes are marked with circles.
The node whose $id=0100$ is additionally ``assigned'' with $id_1=1100$ when it's class $c=1$ (showing as a ghost star in the illustration), and $d'$ yield distance $1$ for key $k=1101$, which is the smaller one between the original distances $d(id,k)$ and $d(id_1,k)$.
When $c=2$, two more identities are assigned to the node, and so on.
As the result, the node is getting closer to more keys in the hash space, and it will be picked for storing more and more keys as its class increases, marked with the gray regions.
The storing key range of a node is approximately doubled as its class increases by one, which indicates its storage capacities doubles.
Eventually, the storing key range is proportional to the node's capacity, which means the likelihood of receiving store request is proportional to the capacity.

While the final effect is similar to what virtual node achieves, the fundamental difference between it and the classified distance approach is that we are not \emph{actually} assign multiple identities to a (physical) node.
The DSNs' assumption about each node identity identifies a unique physical node (\ie failure domain) still holds.
Instead of indirectly express our heterogeneous intent to an unmodified DHT, classified distance extends the DHT to be able to be aware of the heterogeneity by itself, \ie, its consistent hashing scheme now accepts extra class values indicating the heterogeneity.
We argue that modify the DHT design is necessary to express both the storage heterogeneity and the \emph{correct} storage failure correlation.

In order to support classified distance, the retaining policy of node records and the iterative lookup procedure (\autoref{sec:bg:dht}) need to be modified accordingly.
We refer to future work for these details and a reconfiguration protocol for nodes to adjust their classes based on the dynamical changes of their storage capacities.
Noticeably, nodes must relocate the placement groups of the stored data and transfer them away if necessary before decrementing their classes to avoid DHT forward the following accessing to the reallocated nodes of the placement groups while they are not storing the data.

\paragraph{The power of two random choices (2RC)\@.}
As discussed previously, classified distance, which corresponds to the naive approach, leaves a small chance for forwarding the store requests to the nodes with less available storage space.
To counter this, we introduce 2RC into Kademlia's lookup procedure.
Each key is hashed twice with distinct hashing algorithms, and for brevity, we say that each data has two distinct keys.
The lookup procedure will discover the placement groups for both of the keys.
Then, if the node is storing or modifying the data, the store request goes to one of the placement groups whose nodes have more available space.
Otherwise, if the node is retrieving the data, the retrieve request is sent to both of the groups and the one storing the data will respond.

In most other practice, 2RC picks two (homogeneous) backend nodes with uniform randomness.
However, in our case, it is used in conjunction with a biased randomness yielded by the classified distance, which help it to perform better in the heterogeneous case.
Before the whole storage network is nearly saturated (by when our goal of optimizing overall utilization has been nicely done!), the nodes with larger capacities probably have more available storage spaces than the smaller ones.
The classified distance reduces our chance to pick those small nodes, and the chance of picking two small nodes at the same time is even smaller, only when we will first utilize the nodes with less available space.

In conclusion, the design of \dht consists of two components at different \emph{scales}.
The classified distance performs at the largest scale, globally affecting all nodes but with certain rigidity and approximation.
2RC, on the other hand, performs at the smallest scale, only affecting nodes from two placement groups at a time, but provides the most accurate adjustment.
By combining both components, \dht can optimize the effective overall utilization as desired.
Next, we present our preliminary results, showing \dht's effectiveness.

\paragraph{Node class and classified {\normalfont \texttt{xor}} distance.}
\dht performs a \emph{macro} differentiation on the nodes through a \emph{classification}.
In \dht every node is assigned a \emph{node class}, which participants in calculating the node's distance to an \vid:
\begin{verbatim}
dist(id,target_id,class) = (id^target_id) & (~0>>class)
\end{verbatim}
That is, the Kademlia's \texttt{xor} distance is masked out the highest bits, and the number of masked bits equals node's \vclass.
This is called the \emph{classified {\normalfont \texttt{xor}} distance}.
\autoref{fig:distance} shows an example of the same node with different classes.

The effect of node class is similar to virtual node.
The classified \texttt{xor} distance for class 0 is identical to the original \texttt{xor} distance in Kademlia, and corresponds to one virtual node.
For class 1, the distance is same as calculating the original \texttt{xor} distance for both the node's \vid and its ``dual'' which flips the first bit of \vid, and takes the smaller distances of the two.
This effectively ``spawns'' two virtual nodes at the corresponding \vid{}s.
Similarly, we have class $c$ equals to have $2^c$ virtual nodes.
However, with node class each node still has one single \vid, so \ffind will only include each physical node at most once, which is unlike with virtual nodes where \ffind may return multiple \vid{}s that belong to the same physical node.

\paragraph{The power of two random choices (2RC).}
The node class is a powerful, exponential differentiation.
However, it is not without shortcoming.
If a node is discoverable for a \fput, it must be discoverable for the following \fget as well, otherwise the stored data cannot be retrieved.
This symmetry forbids us to adjust node class according to its current AC.
\lijl{We can discuss why this violates our target properties of \dht.}
In \dht the node class is set based on its total capacity.
Effectively the nodes are classified into different (exponential) levels of sizes, and we assign an initial discoverability for each level accordingly.

However, that does not reflect the \emph{real time} differences.
Even for nodes that are classified into the same size level, their AC probably differs at a given instant.
This may due to probabilistic fluctuation of their empirical discoverability, or the contents stored on them expire at different rates.

To compensate for the real time dynamics, \dht performs \emph{micro} differentiation with 2RC.
However unlike the typical employment of 2RC that pick the nodes with lighter load, \dht picks the nodes with more AC.
By \emph{balancing} the AC of the nodes, \dht manages to \emph{differentiate} the discoverability of nodes with different AC, as the nodes with more AC will be more discoverable until their AC is balanced with the others.

\paragraph{Simulation setup.}
We evaluate \dht with a simulated DSN.
Without further clarification, the simulations are performed with 12k nodes, and each node can store $2^{10}$ contents at minimum and $2^{17}$ at maximum.
So the node class values are between 10 and 17.
The node capacities follow a shifted Zipf distribution~\cite{zipf} with skewness set to $1$.
Besides \dht, we also simulate a vanilla Kademlia DHT as the compared baseline.
We replicate each content with 3 copies, \ie, $r=3$.
Finally, we repeat each simulation 100 times and report the average and error of the results.

\begin{figure}
    \centering
    \includegraphics[width=0.7\linewidth]{data/simulation/graphs/util}
    \caption{Overall utilization that DSNs can effectively achieve.}
    \label{fig:util-loss}
    \Description{}
\end{figure}

Firstly, we perform 10 million storing attempts with the simulated DSNs.
With \dht all storing attempts are successful, and no node is running out of space. 
The results of Kademlia are shown in \autoref{fig:overwhelm} and described in \autoref{sec:bg:problem}.

Next, we further perform a stress simulation by continuously storing random data (with random eviction on node storage exhaustion) until data loss, and report the overall utilization in \autoref{fig:util-loss}.
We simulate with different skewnesses of node capacities, from 1 where the capacities are highly diverse, to 2 where most of the nodes have the same $2^{10}$ capacity.
We further perform ablation study on the effectiveness of classified distance and 2RC designs.
The results show that both designs provide improvement, but in distinct ways.
The classified distance is effective when the node capacities are diverse, but degrade to Kademlia's performance when the skewness is high and most nodes have the same (lowest) node class.
2RC, on the other hand, yields perfect utilization under high skewness, but becomes ineffective when the capacity is significantly heterogeneous.
Finally, \dht combines the improvement by both of them and outperforms Kademlia by more than 60\% utilization at any skewness, and can reach at most 100\% utilization at high skewness.
The simulation shows that \dht accomplish its goal of optimizing effective overall utilization, and both designs are effective in their expected ways.

We continue evaluations with micro-benchmarks to analyze \dht in depth.
In \autoref{fig:freq} we show the CDF and per-class averages of the storing likelihoods assigned by classified distance and Kademlia's vanilla distance.
In this simulation we generate 1 million data keys with uniform randomness.
The storing likelihoods of the nodes are represented with the frequencies of the nodes appears in the placement groups. 
To clearly demonstrate how well DSNs handle the heterogeneous nodes, we report the storing likelihoods of the storage units, which are the node likelihoods divided by the nodes' storage capacities.
The CDF shows that \dht's likelihood is more balanced than the Kademlia's one, which has a long tail \ie some storage units have much higher likelihood to be utilized than the others.
The per-class averages reveal the source of this difference: in the Kademlia, the nodes with lower classes has exponentially higher likelihood.
This is because those nodes has exponentially smaller capacities, but this heterogeneity is not respected by Kademlia's distance definition and those nodes are assigned with overwhelming storing likelihoods.

The next evaluation studies how DSNs perform on equalizing the available spaces of the storage nodes.
We store the same number of data into both Kademlia and \sys so that the first node runs out of its space in Kademlia.
We snapshot the available spaces of the nodes at this point in both networks.
In \autoref{fig:ac-distr} we plot the distribution of the available spaces of the nodes with $2^{10}$ capacity on the left, and we average the available spaces of nodes of different sizes and plot them on the right.
In \dht the nodes with the smallest $2^{10}$ capacity have basically 0 utilization and have all their capacities available, and the nodes with larger capacities have significantly less available spaces compared to Kademlia.
This shows that \dht can preserve the available spaces on small nodes by preferring the larger nodes, while Kademlia already utilizes these nodes and starts to exhaust some of them.
The saw-shaped line of \dht is because of the error introduced by node class: the node capacity is approximated with the closest power-of-two, which causes over- and under-utilization of nodes whose capacities are in the middle of consecutive power-of-two.
