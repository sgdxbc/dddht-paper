Do state-of-the-art storage systems offer strong durability guarantees in our newly defined fault model?
To test our hypothesis, we run simulations with correlated failures  modeled after our failure generators (\autoref{sec:model:model}).
Note that these simulated failure correlations are not based on any real-world traces, as realistic failure domains are hard to determine.
We, however, believe our simulations are representative of correlated failures in decentralized environment.

\subsection{Simulation Overview}

Our simulation program consists of an operational fault model as described in \autoref{sec:model:model} and a target protocol that attempts to perform repairs to recover durability.
The simulation is performed in discrete \emph{steps}.
The step interval is determined by the responsiveness of the protocol.
Each step is simulated in two phases.
In the first phase, nodes fail and join according to the failure generator.
Next, the target system performs any maintenance protocol.
The simulation collects key statistics per step, including average churn rate, the redundancy level, and most importantly, the fraction of durable data, \ie, objects whose non-failing fragments are above the recovery threshold.
The simulation starts by populating some data objects into the storage network.
No new objects are subsequently stored into the network.
The simulation then follows the above procedure until a maximum number of steps is reached, or when all data objects are lost.

\paragraph{Failure generator}
The failure generator generates two types of failure domains.
%The first kind is for independent failures, one failure domain for each node and contains only that single node.
Independent failures, \ie, failure domain size of one, have a fixed failure rate.
They are essentially the ``background'' failures that ensure every node eventually leave the system.
%The second kind of failure domains contain at least two nodes and represent correlated failures.
For failure domains with more than one node, the size of the failure domain follows a geometrical distribution.
The distribution models the realistic expectation that larger domains are rarer than the smaller ones.
The failure rate of a failure domain follows an exponential distribution.
%, such that higher failure rate is more unlikely.
Note that the failure rate is domain size agnostic: It is entirely possible for large domains to have high failure rates.

We vary the average domain size while keeping the average node failure rate constant by adjusting the failure rate distribution accordingly.
With this setup, the target protocol undergoes executions with comparable churn rates, with only varying correlations.

\paragraph{Evaluated protocols}
We implement a representative decentralized storage protocol, similar to Glacier~\cite{glacier}.
In this protocol, the fragments are stored on the $n$ consecutive storage nodes whose IDs are immediately adjacent to the object hash.
The object is recoverable as long as $k$ fragments are alive.
Other decentralized storage solutions share similar placement group selection policies.
%Prior decentralized storage systems pick placement groups with similar strategies that are optimized for performance.
We vary $n$ and $k$ to simulate different placement group sizes and redundancies.
We also simulate a baseline protocol that distributes fragments to random nodes and never performs repair.

\subsection{Simulation results}

We simulate a storage system with 1K nodes.
All simulations last at most 1 million steps.
A constant $10^{-5}$ independent failure rate is applied to all storage nodes.
By default, an $n = 8$, $k = 5$ erasure code is used in both the target protocol and the baseline.

\paragraph{Tolerating independent failures}
We first simulate only independent failures.
As shown in \autoref{fig:simulation-all}, the target protocol tolerates independent failures effectively, confirming claims from previous works.
Failure of individual nodes does not lead to data losses, as the protocol performs repair to recover the redundancy level within the same step.
Multiple independent failures can happen in the same simulation step, but the probability of simultaneous failures in the same placement group decreases exponentially as the number of failures increases.

\paragraph{Correlated failures.}
We now add correlated failures with different average domain sizes, but keep the average churn rate per step to 2\% of the system size.
As shown in \autoref{fig:simulation-all}, introducing correlated failures immediately results in data losses in the target protocol.
%The impact of correlated failure is huge.
When more than 1\% of storage nodes have correlations, the system fails catastrophically to maintain durability.

\paragraph{Increase redundancy.}
Next, we study the impact of increased redundancy by scaling up $n$ while fixing $k$.
Adding more redundancy improves durability, but at the expense of higher storage overhead.
Our simulation shows that the system is only durable in 1 million steps when the overall redundancy level is above 37\%, which is a significant degradation in overall capacity.

Can we improve durability without increasing redundancy?
We notice that, as $n$ increases, both the redundancy level and the placement group sizes are affected.
Larger placement group sizes help distribute fragments to more nodes, which mitigates the impact of correlated failures.
Based on this observation, we perform the next simulation.

\paragraph{Scale up placement groups.}
In this simulation, we keep a constant 1.6x redundancy, and increase both $n$ and $k$.
As shown in \autoref{fig:simulation-all}, the durability of the system indeed improves.
With an $n = 24$ and $k = 15$ erasure code, the target protocol is perfectly durable in the simulated duration without incurring additional redundancy.

\paragraph{Takeaways.}
Our simulation results demonstrate that both redundancy levels and placement group sizes impact system tolerance to correlated failures.
Though adding redundancy can be effective, it comes at the cost of reduced system capacity.
Moreover, previous studies~\cite{irisstore} have shown that its effectiveness becomes marginal as redundancy grows.
On the other hand, enlarging placement groups effectively reduces the impact of smaller-scale correlated failures.
It, however, has no impact on the overall storage capacity.
