A proper repair threshold $k_0$

should be selected, and the VRF should be configured as
(a) it selects at least $k_0$ peers for each epoch with high probability, so the peers do not observe unhealthy objects by false positive and repair too soon, and
(b) it selects at most $k_0/B$ peers for each epoch with high probability, so there's no more than $k_0$ faulty peers get selected in every epoch and ensure safety.

\textbf{Program implementation.}
Base on libp2p-rust. Use TCP transport with Noise protocol framework \cite{noise} for authentication and libp2p's Mplex protocol for stream-muiltplexing.
The implementation mainly consists of two parts: gossip protocol and fragment exchange protocol.
Gossip protocol is built with libp2p's Gossipsub protocol, using 3 topic STORE, QUERY and SHOW for two operations and persistence proof.
Gossipsub will randomly send the message to a set of mesh peers, i.e. 10 random peers in the network.
This outbound congestion control makes sure a popular peer's CPU and bandwidth is not overwhelmed by gossip.
The custom fragment exchange protocol is simple one-shot RPC to allow peers to push and pull fragments from another peer.
The rateless erasure coding implementation uses wirehair \cite{wirehair}, which provided tiny $\epsilon$ like RaptorQ while also highly optimized to push encoding/decoding threshold to extreme.
Homomorphic hashing is not implemented yet, instead peers do optimistic verification on the final recovered object.
Each peer is equipped with an Ed25519 key pair. The key is used both for signing messages and generating random hash in VRF.
The system is set up with standard peer discovery mechanism without any centralized service.
