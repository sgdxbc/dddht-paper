Our implementation is based on libp2p-rust. \sgd{cite}
The transport layer is based on TCP, equipped with a multiplex protocol to reuse connection to peers. 
The secure layer negotiates using Noise protocol framework \cite{noise}, and the encryption channel is established with 25519 DH functions, ChaChaPoly cipher functions and SHA256 hash function.

The implementation uses libp2p's \texttt{identify} protocol to exchange peer's information, e.g., public key and listening addresses.
The DHT operations are performed with libp2p's \texttt{kademlia} protocol.
We also leverage the protocol to bootstrap the peers.
Some DHT operations like \texttt{FIND\_CLOSEST} and \texttt{STORE\_RECORD} are iteratively performance and has logarithm overhead relative to network scale.
As the result, if too many operations are issued concurrently, they map impact the whole system and the operations' tail latencies may increase dramatically.
As the result, we throttle the number of concurrent DHT operations according to average message latency.

We implement the protocol described in section \ref{sec:protocol} with libp2p's \texttt{request-response} protocol.
Notably, for certain message types like repair request, there's no according response message by definition.
To conform with libp2p's requirement a dummy response is sent.
The messages are serialized with Protocol Buffers, following libp2p's convention.

The rateless erasure coding implementation uses wirehair \cite{wirehair}, an $O(1)$ time fountain code implementation.
The coding has extremely high throughput as shown in \sgd{ref microbench}, and it is expected to recover the original message with $k + 0.02$ fragments.

The client sends fragments for more than $\kout$ indexes for \texttt{PUT} operation. 
Because it is possible to have some indexes not select any peer successfully.
Also, the peer selection relays on iterative DHT operations, which makes its tail latency suboptimal.
By sending extra fragments and wait for the first $\kout$, and \texttt{PUT} can be finished in a much more bounded time.
The extra fragments will be garbage collected soon automatically by the protocol.
