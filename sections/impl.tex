We implement \sys atop the open-source libp2p-rust library~\cite{libp2p}.
We use TCP as the transport layer and apply a multiplex protocol to reuse connection to peers.
The security layer comprises the Noise protocol framework~\cite{noise} for negotiation, and encryption channels established using 25519 DH, ChaChaPoly cipher, and SHA256 hash functions.

Our implementation uses libp2p's \texttt{identify} protocol to exchange peer information, e.g., public key and listening addresses.
libp2p's \texttt{kademlia} serves as our DHT, and we leverage the same protocol to bootstrap the peers.
Certain DHT operations, such as \texttt{FIND\_CLOSEST} and \texttt{STORE\_RECORD}, require logarithmic steps in the size of the  network.
Consequently, performing an unbounded number of DHT operations in parallel would negatively impact the system performance.
We therefore throttle the number of concurrently issued DHT operations based on average message latency.

Request processing listed in \autoref{sec:protocol} are implemented using the \texttt{request-response} protocol in libp2p.
Notably, certain message types like \mtype{RepairRequest} require no responses by definition.
To conform with libp2p, a dummy response is sent.
All messages are serialized using Protocol Buffers~\cite{protobuf}.

We use wirehair \cite{wirehair}, an $O(1)$ time fountain code implementation, as our rateless erasure code.
Wirehair not only attains high performance, it can also recover the original data with an expected $k + 0.02$ fragments.

Our implementation attempts more than $R$ encoding indices for each \texttt{PUT} operation, in anticipation of unsuccessful peer selection for some indices.
This approach brings additional latency benefit.
%Also, the peer selection relays on iterative DHT operations, which makes its tail latency suboptimal.
Given the long tail latency distribution of DHT operations, by sending extra fragments and waiting for the first $R$, latency of \texttt{PUT} becomes more predictable.
The extra fragments are later garbage collected by the protocol.
