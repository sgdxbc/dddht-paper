Permissionless blockchains~\cite{bitcoin,ethereum} build fully decentralized ledgers, enabling cryptocurrencies and broader set of applications without centralized trust.
At the core of a blockchain protocol is state machine replication~\cite{smr}, where all blockchain participants execute the same sequence of transactions to derive the same state machine.
However, as blockchains gain popularity and expand their use cases, the size of the state machine continues to grow.
For instance, there has been proposals to support images, videos, AI models, and other large data in blockchains.

Requiring all blockchain participants to maintain this growing state machine is infeasible.

Decentralized storage offers an attractive solution to this scalability challenge.
\lijl{Cite existing decentralized storage here.}
Instead of storing large state (e.g., AI models) directly on-chain, the state is maintained on off-chain storage servers, while the blockchain nodes only save small state hashes.
Unlike a blockchain, a decentralized storage system can perfectly scale its storage capacity by incorporating more storage servers into the network.
In the meantime, such storage network maintains key properties of a blockchain, such as decentralization and Byzantine fault tolerance.

This approach of scaling blockchain, however, faces a data availability challenge.
\lijl{Is it okay to reuse the DA terminology here? Or should we just use durability?}
A blockchain protocol guarantees that the system is available when up to $1/3$ of the participants are faulty.
To maintain this strong guarantee, the state offloaded to the storage network also needs to be available when $1/3$ of the storage network is faulty.
Otherwise, a transaction accessing an unavailable offloaded state would stall the entire blockchain state machine.

Guaranteeing data availability in decentralized storage is inherently harder than a blockchain.
Blockchain applies full replication;
when any $1/3$ of the nodes fail, the remaining nodes always possess the full state.
For scalability, decentralized storage assigns each data only to a subset of storage nodes.
The assignment protocol is therefore critical to data availability.
Data loss can happen when all copies of a data are assigned to faulty servers or nodes without sufficient storage capacity.

A well-established approach to assigning data to servers in a decentralized network is using distributed hash tables (DHTs)~\cite{chash,chord,maymounkov2002kademlia}.
A DHT projects both data and node hashes onto the same hash ring;
an object is assigned to $n$ nodes whose node hashes are closest to the object hash on the ring.
The assignment is done in a fully decentralized manner;
no centralized entities control or maintain the mapping metadata.
The approach is also amenable to a permissionless setting: Nodes can freely join and leave the network at any time.

DHTs are effective at balancing request load across nodes in a network.
They, however, make a critical assumption that every node always has sufficient storage capacity to store all mapped objects.
In a permissionless network where participants exhibit significant heterogeneity, such assumption is no longer valid.
Even when there is sufficient aggregated capacity in network, the available capacity (AC) on each node can have large variance due to different initial capacity, request distribution, and lifetime.
We validate this hypothesis using simulations in \autoref{sec:bg:problem}.
Variance in AC directly leads to degraded data availability.
Since DHTs distribute storage requests uniformly across the network, a node with insufficient AC has to either reject a storage request or evict existing objects when other nodes still have spare capacity, resulting in lower redundancy level.
The issue is even more severe when the network scales down (e.g., nodes churning and network partitions).

Differentiable Discoverability DHT (\dht) is a decentralized storage network that performs efficient random placement with DHT but \emph{differentiate} workload of storage nodes based on their available capacities.
In \dht, storage nodes are highly unlikely to be overwhelmed given that the total storage supply of DSN is sufficient for storing the contents with targeted redundancy level.
\lijl{Make sufficient overall capacity an assumption, and state the global AC property.}
This means that \dht can deliver strong durability guarantee: the probability of data loss can be derived from the redundancy level, the portion of storage capacity that is controlled by faulty nodes and the skewness of storage capacities across the nodes.
Thus, given the faulty portion and the skewness of capacity, we can always determine a minimum redundancy level so that the probability of data loss is negligible.
\lijl{Is the point that prior DHTs can't derive this redundancy level, or their minimum redundancy level is higher than us?}
This makes \dht to be the first work that can guarantee durability with the assumption of size-limited, permissionless and Byzantine storage nodes.

We argue that the problem of virtual node approach is because it attempts to solve the problem ``on the back of'' DHT (by building another layer on top of it).
\lijl{Is virtual node the only approach to address this issue? The previous sentence might make the scope a bit narrow.}
Instead, we directly modify the DHT protocol to differentiate the \emph{discoverability} of nodes.
While previous works define the discoverability of a node as a binary property of whether the node is included in any \ffind results, we extend this definition to an ordinal value to represent how \emph{frequent} the node appears in the results of \ffind that the target \vid is uniformly distributed in the \vid's domain space.
In \dht the discoverability of nodes is adjusted according to the nodes' AC, and the nodes with higher AC, \ie, are capable to handle more storing requests, are more discoverable, thus more storing requests are dispatched to them.
On the other hand, the nodes that are running out of AC are least discoverable, and DSN would not allocate much placement groups including them to avoid overwhelming them.
\lijl{``DSN allocate placement groups'' sounds like a centralized approach.}

Based on Kademlia DHT, \dht introduces two novel modifications to differentiate the discoverability of storage nodes with different AC.
The first one is to perform \emph{macro} differentiation of storage nodes of different sizes with \emph{node class}.
This is a highly effective global differentiation but approximates the nodes' AC with their total capacities, and it is a rather static method \ie the node class cannot be adjusted based on the current AC.
\lijl{After applying node class, what properties do the system have? What are the remaining ``errors''?}
To compensate the error, we use \emph{the power of two choices} (2RC) for \emph{micro} differentiation.
It can perform accurate local differentiation but only among few nodes from two candidate placement groups.
Combining the two methods results in surprisingly balanced AC, and nodes only start to be overwhelmed when the whole system is about to be so.

{\color{gray}
The node class makes a similar effect to virtual node: a node's discoverability is doubled when its node class is increased by one, effectively equals to double the number of virtual nodes in that approach.
However, node class is implemented by modifying the Kademlia's \texttt{xor} distance definition: the highest bits of the \texttt{xor} distance are masked out and the number of masked bits equals to the node class.
The node class mechanism preserves the one-to-one mapping between node \vid and physical storage node, so it does not bring additional failure correlations, and it allows nodes to decrease their discoverability without increasing the risk of losing data.

Unlike previous works \xxx{cite} that leverage 2RC to balance the workload on every node, \dht uses 2RC to balance the AC of the storage node.
In \dht, \ffind operation discovers placement groups for the hash of the key addition to the key as an alternative candidate.
The storage nodes from the two candidate placement groups report their current AC, and \ffind will pick the placement group that with higher \emph{minimum} AC.
By doing this in every \ffind, the discoverability of storage nodes are differentiated according to their AC at the time of \ffind.
