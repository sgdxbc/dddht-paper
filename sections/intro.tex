A permissionless system is in turn modeled as a series of \emph{failure events} that
\begin{itemize}
    \item In every failure event, all storage nodes from a specific failure domain simultaneously fail in the time unit (which is approximated as an instant).
    \item In each time unit, all failure domains \emph{independently} fail according to their failing rates.
    \item Since failure domains overlap with each other, a storage node fails at a time unit if at least one of the failure domains it belongs fail.
    The failed storage nodes permanently leave the system, so each failure domain can only fail once.
    \item The system's \emph{churn rate} is measured as the expected number of failed nodes in every time unit.
    For simplicity, we assume the system remains constant scale, so in every time unit, the number of fresh storage nodes joining the system equals to the number of failed nodes of that time unit.
    \item As the fresh nodes joining, they immediately form new failure domains in combination of all the other nodes.

\end{itemize}

We are witnessing a technological paradigm shift to move away from service centralization, a hallmark of the cloud computing and web services industries in the past two decades.
This \emph{decentralization} movement is catalyzed by the growing concern over content censorship~\cite{twitter_censorship}, data misuse~\cite{fb_misuse}, monopolistic practices~\cite{google_antitrust}, and single point of organization failure~\cite{ftx_debacle}.
Following the success of the Bitcoin~\cite{bitcoin} and Ethereum~\cite{ethereum} blockchains, a burgeoning of decentralized services are being deployed, including cryptocurrency exchanges~\cite{uniswap,coinbase}, content delivery network~\cite{meson}, domain name service~\cite{handshake}, messaging~\cite{matrix}, and computation~\cite{dfinity}.

An attractive avenue for decentralization is data storage~\cite{ipfs,filecoin,ar,storj}.
Compared to their centralized counterparts~\cite{amazon_s3,google_cloudstore,dynamo,dropbox}, decentralized storage is better positioned to address the issues of data breaches, censorship, content availability, and high storage cost.
We have already seen successful large deployment of decentralized storage systems:
The InterPlanetary File System (IPFS)~\cite{ipfs} has over 300 thousand active participating peers globally, collectively storing more than 1000 PB of data.

A critical requirement for decentralized storage systems is \emph{data durability}, particularly for deployments that store data which represents high-value assets.
Ethereum, for instance, holds account records that are worth more than \$233 billion in total~\cite{eth_market_cap}.
Non-fungible tokens (NFT) listed on blockchains such as Solana~\cite{solana}, Polygon~\cite{polygon}, and Arbitrum~\cite{arbitrum} are already worth tens of billions of dollars~\cite{nft_stats} and quickly growing.
These high-value data cannot be stored on centralized systems due to anti-censorship requirements; neither can they be stored on best-effort P2P solutions like BitTorrent~\cite{bittorrent} and IPFS, as any data loss will have high financial implications.

Decentralization presents fundamental challenges to the durability guarantees of a storage system.
To handle data loss caused by failures, redundancy-based approaches such as replication~\cite{smr,pb,pbft} and erasure coding~\cite{reed-solomon} are commonly used.
These solutions work well in a centralized deployment, where operators have full control over the infrastructure, failure domains, and placement groups with minimum correlated failures.
A decentralized system, on the contrary, has no central authority to manage the behavior and trustworthiness of the participants;
nodes join and leave the system at high churn rate;
there exists high variance in node performance, reliability, and network conditions;
adversarial behaviors are prevalent.
In such open and asynchronous environment, traditional redundancy schemes lose their effectiveness in preventing data losses.
Recently, more than 1600 TiB of data on the Filecoin~\cite{filecoin} network lost all replica copies simultaneously~\cite{filecoin_loss}.

In this work, we propose a new decentralized storage system, \sys, to address this durability challenge.
At the core of our approach is two durability principles we identified for decentralized storage, namely \emph{information asymmetry} and \emph{data uniformity}.
The information asymmetry principle states that, in the presence of targeted adversarial attacks, data durability can only be guaranteed if some metadata information is asymmetrical in the system.
The intuition behind the principle is that if adversaries have equal and complete view of storage metadata, they can concentrate attack powers on specific nodes to break durability of certain objects.
The data uniformity principle says that to maximize durability, encoding of all stored objects should be distributed uniformly random across storage nodes.
The principle hinges on the unpredictability of churning and adversarial behaviors in an open, decentralized system.

Following the information asymmetry principle, \sys uses a \emph{rateless erasure code} to generate a virtual stream of encoding chunks for each object.
To create asymmetry, a client uses its \emph{private key} to materialize the infinite stream into a finite set of randomly selected chunks.
Critically, the mapping between the materialized chunks and the original object is \emph{opaque} to all participants except the client.
With sufficient objects stored in the system, adversaries have negligible probability to attack enough materialized chunks of the same object to compromise durability.

This opaque object-to-chunk mapping, unfortunately, also precludes object repair.
To ensure long-term durability of the object, \sys applies erasure coding a second time for each encoding chunk with only public information.
Here \sys chooses to use rateless code again: Compared to conventional maximum distance separable code (MDS), rateless code offers better fault tolerance properties in a highly asynchronous network and faulty environment.
Rateless code support efficient \emph{large code} encoding.
The large number of code symbols improves statistical reliability of the chunk without increasing redundancy.
More importantly, it eschews the need for time-sensitive encoding repair --- an impractical requirement in a decentralized network --- and permits repair at a steady average-rate.
The bigger symbol space also facilitates nodes to perform repair \emph{independently}, avoiding costly coordination.

To comply with the data uniformity principle, \sys applies \emph{verifiable randomness} to select randomly distributed nodes to store code symbols.
The procedure avoids centralization by using verifiable random function~\cite{vrf} to determine participant eligibility.
Selection results are unforgeable and publicly verifiable.
Randomness and verifiability of the selection outcome ensures that sufficient code symbols are stored on non-faulty nodes, even when significant portion of the participants are adversarial.
