\section{Introduction}
\label{sec:intro}

We are witnessing a technological paradigm shift to move away from service centralization, a hallmark of the cloud computing and web services industries in the past two decades.
This \emph{decentralization} movement is catalyzed by the growing concern over content censorship~\cite{twitter_censorship}, data misuse~\cite{fb_misuse}, monopolistic practices~\cite{google_antitrust}, and single point of organization failure~\cite{ftx_debacle}.
Following the success of the Bitcoin~\cite{bitcoin} and Ethereum~\cite{ethereum} blockchains, a burgeoning of decentralized services are being deployed, including cryptocurrency exchanges~\cite{uniswap,coinbase}, content delivery network~\cite{meson}, domain name service~\cite{handshake}, messaging~\cite{matrix}, and computation~\cite{dfinity}.

An attractive avenue for decentralization is data storage~\cite{ipfs,filecoin,ar,storj}.
Compared to their centralized counterparts~\cite{amazon_s3,google_cloudstore,dynamo,dropbox}, decentralized storage is better positioned to address the issues of data breaches, censorship, content availability, and high storage cost.
We have already seen successful large deployment of decentralized storage systems:
The InterPlanetary File System (IPFS)~\cite{ipfs} has over 300 thousand active participating peers globally, collectively storing more than 1000 PB of data.

A critical requirement for decentralized storage systems is \emph{data durability}, particularly for deployments that store data which represents high-value assets.
Ethereum, for instance, holds account records that are worth more than \$233 billion in total~\cite{eth_market_cap}.
Non-fungible tokens (NFT) listed on blockchains such as Solana~\cite{solana}, Polygon~\cite{polygon}, and Arbitrum~\cite{arbitrum} are already worth tens of billions of dollars~\cite{nft_stats} and quickly growing.
These high-value data cannot be stored on centralized systems due to anti-censorship requirements;
neither can they be stored on best-effort P2P solutions like BitTorrent~\cite{bittorrent} and IPFS, as any data loss will have high financial implications.

Decentralization presents fundamental challenges to the durability guarantees of a storage system.
To handle data loss caused by failures, redundancy-based approaches such as replication~\cite{smr,pb,pbft} and erasure coding~\cite{reed-solomon} are commonly used.
These solutions work well in a centralized deployment, where operators have full control over the infrastructure, failure domains, and placement groups with minimum correlated failures.
A decentralized system, on the contrary, has no central authority to manage the behavior and trustworthiness of the participants;
nodes join and leave the system at high churn rate;
there exists high variance in node performance, reliability, and network conditions.
More critically, adversarial behaviors are prevalent in a decentralized deployment.
With attack power proportional to the system size~\cite{bitcoin,ethereum,pbft}, adversaries can compromise significant subset of the system to break data durability.
In such open, asynchronous, and adversarial environment, traditional redundancy schemes lose their effectiveness in preventing data losses.
Recently, more than 1600 TiB of data on the Filecoin~\cite{filecoin} network lost all replica copies simultaneously~\cite{filecoin_loss}.

In this paper, we propose a new decentralized storage system design, \sys.
\sys guarantees data durability even when \emph{any} $\frac{1}{3}$ of the system is compromised by adversaries.
This level of fault tolerance is traditionally only possible with Byzantine Fault Tolerant (BFT) protocols that fully replicate each object on all participating nodes.
We show that prior storage solutions~\cite{farsite,oceanstore,cfs,glacier,carbonite,irisstore,ipfs}, which partition the system into placement groups, all suffer data losses in the presence of strong adversaries.
Fully replicating each object, however, limits the overall system storage capacity to that of a single node.
\sys also enables linear capacity scaling when new storage nodes join.
To our best knowledge, \sys is the first storage system that offers scalable storage capacity without compromising Byzantine fault tolerance guarantees.

\sys achieves these strong properties by proposing a radical design.
The entire system consists of a \emph{single} placement group.
By distributing data of each object to all storage nodes, \sys guarantees durability even in the presence of strong adversarial behaviors, without relying on failure domain assumptions.
To scale the system storage capacity, \sys \emph{decouples} object redundancy from data distribution.
Each object is encoded using an erasure code with a constant redundancy level based on the fault tolerance requirement, independent of the placement group size;
\sys then distributes the object and its redundancy \emph{evenly} across all nodes in the system.

Realizing the \sys design, however, faces several challenges.
First, decentralized deployments have large and dynamic system sizes~\cite{ipfs}.
At such scale, traditional erasure coding schemes become computational infeasible;
they also only work for placement groups with fixed sizes.
Second, recoverability of erasure codes requires distributing \emph{unique} fragments to each node.
Running BFT consensus protocols for fragment distribution at our target scale is expensive and slow.
Lastly, since \sys distributes fragments of an object system-wide, overhead of object repair in both network bandwidth and computation can become impractical.

To address these challenges, \sys applies a \emph{rateless erasure code}.
Unlike traditional maximum distance codes (MDS) commonly deployed in storage systems, a rateless code generates an \emph{infinite} sequence of encoded fragments.
\emph{Any} $k + \epsilon$ unique fragments can recover the original object.
When storing an object, each \sys node independently samples \emph{random} fragments from the infinite encoding sequence.
Randomness and the infinite encoding space ensure negligible fragment collision, while eliminating the need for BFT consensus.
Moreover, when the system size scales, newly joined nodes can independently generate new, unique fragments, without re-encoding existing fragments.
Lastly, we propose a new rateless code construct, the Optimal Regeneration Code (\code), based on Luby Transform codes.
\code enables object repairs to completely eschew regeneration the original objects, making the repair process practical under our \sys design.

\sys is a practical design.
In a world-wide deployment, \sys maintains \fn{Put} and \fn{Get} latency within 1.7x and 1.8x comparing to a mainstream DHT-based storage.
Latency of \sys remains stable while the system scales up.
\sys also sustains a 238~MB/s throughput, comparable to the DHT storage, even with limited node bandwidth resource.
Critically, \sys guarantees data durability, while the DHT store loses data in the presence of adversaries.
Using simulation, we show that \sys maintains \emph{constant} redundancy regardless of system scales.
We also prove that \sys can properly adjust redundancy in dynamic systems, and has lower repair overhead than the DHT store.
