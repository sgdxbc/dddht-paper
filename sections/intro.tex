\section{Introduction}
\label{sec:intro}

\begin{outline}
Blockchains are important consensus facilities for decentralized systems.

Challenge: the state size of blockchains overwhelms consensus nodes.

Approach: offload immutable data \ie \emph{contents} to permanent storage and access to them off-chain.

Notice: blockchain implicitly guarantees durability state.
Any content that is referenced by the state, \ie logically still part of the state, must obey this guarantee as well.

Where to store then?
Observation: much more nodes are available than BFT can scale.
Nowadays (even permissionless) BFTs seek high quality \emph{professional} consensus nodes.
Unreliable devices cannot meet the requirement and only serve as thin clients, and their storage capacity is underutilized.

Introduce decentralized storage network (DSN).
Make use of the spare storage capacity in the decentralized system.

Introduce storage nodes.
Too slow/unavailable to participant consensus, but can contribute storage capacity.
Key point: storage nodes share the same Byzantine fault model with consensus nodes.

One approach: storage auditing \eg Filecoin.
Problem with Filecoin: impose high durability requirement on each \emph{individual} participants.
High barriers to entry.
Tricky to design effective incentive when storage nodes expecting high return to cover the cost.

Another approach: incentive-based replication \eg Arweave.
Redundancy is not controllable and probably overwhelming.
Rely on storage nodes to discover profitable storing deals.
\xxx{Elaborate.}

Insight: system should supervise/coordinate for dissemination and repairing, only then DSN can be efficiently built upon on-average reliable storage nodes.
Introduce Swarm.

However, currently such storage systems diverge from BFT in the threat model.
BFT protocols tolerate failures that may come from \emph{any} $\frac{1}{3}$ nodes, while Swarm expects random failure combinations and sparse adversaries.

Goals:
\begin{itemize}
    \item Co-design with BFT.
    No special requirement/incentive regarding durability, enabling wide participation.
    \item As secure as pure BFT.
    If under certain situation a pure BFT system is durable, so should be the DSN.
    \item Bounded \& controllable redundancy.
\end{itemize}

Contributions:
\begin{itemize}
    \item Develop a security model of durability for DSNs that are intended to extend blockchains' capacity.
    \item Analyze current DSNs' durability.
    \item Design \sys, analyze its durability.
    \item Evaluate durability and performance of \sys compared with current systems.
\end{itemize}
\end{outline}
