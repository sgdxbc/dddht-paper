\subsection{Threat Model}

At any time, at most $f$ fraction of all nodes are \emph{under attack}.
The nodes are either themselves faulty, or they are targeted by external attackers.
The nodes under attack may behave arbitrarily.
The adversarial attacker may choose victim nodes based on public channel messages, i.e., gossips.
However, it cannot observe any point-to-point private channel, neither the content nor whether the channel exists.

Notice that this threat model surpasses typical Byzantine model, where attacker cannot choose faulty identity.
\sgd{And it is a little unnecessarily strong, e.g., it allows attacker to forge message sent by victims which may not be possible.}

\subsection{Design}

Informal description of defending several kinds of attacks.

\emph{Outer coding.}
Client applies certain large code to the stored data object, and store the generated fragments, which is called encoded objects, into the system.
This coding ensures both that attacker cannot associate nodes' gossips with data objects, and that certain amount of encoded objects lost can be tolerant.
The former property prevents attacker to target encoded objects of the same data object.
In another word, no matter how attacker chooses the target encoded objects, it's highly unlikely that there are a sufficient number of encoded objects of one data object got attacked.
And the latter property ensure safety when insufficient encoded objects got attacked.

\emph{Inner coding and random selection.}
The system randomly assigns encoded objects to a set of responsible nodes with transferrable authentication.
The selection prevents attacker to target encoded fragments of the same encoded object.
In another word, attacker can only claim to be responsible for an insufficient number of encoded fragments of one encoded object.
And the coding ensure safety when insufficient encoded fragments are claimed to be responsible by faulty nodes.

The inner coding could be any large code, but rateless erasure coding along with VRF provides a convenient way to implement the selection.

The proof of responsibility + redundancy can be replaced by other proof of persistent strategy, e.g., random sampling by Filecoin.
Our approach is more computational efficient than the alternatives and completely decoupled with incentive.
